# 展示数据集

本目录存放公开仓库的**展示用合成线网**：比 `demo/` 大、覆盖更全，用来在本地演示这个应用能做什么。这里的一切都是虚构的：

- 两座城市（示例城、邻江城）、三家运营方、64 座车站、63 个物理区间、8 条运营线路；
- 线路名、车站名、里程和坐标都是为演示编造的，没有从维护者的内部数据包复制任何内容；
- `LICENSE-OSM.md` 的文件名由信封 schema 固定；这里不含 OpenStreetMap 数据，也不含任何署名内容。

## 它演示什么

| 数据里的安排 | 对应界面上能看到的能力 |
| --- | --- |
| 一条环线（`环线`，10 座车站闭合） | 环线展平、环线区间记录、示意图上的闭环画法 |
| 一条带支线的线路（`三号线` 与 `三号线支线`） | 支线记录、两条运营线路共用区间的显示 |
| 两组显式直通对（三号线↔支线、城市快线↔城际线） | 进阶记录里的跨线直通 |
| 一段仍未恢复的临时停运、一段已恢复的临时停运 | 示意图上的停运区间与恢复日期 |
| 一条永久停运线路（`六号线`）、一处永久停运区间（二号线中段） | 永久停运的展示与统计口径 |
| 一家不提供里程的运营方（`示例城市快线`） | 里程未知时，里程与区间/车站按不同算法统计 |
| 一条跨城线路（`二号线` 末段进入邻江城） | 按城市分组的统计 |
| 三组重名车站（跨城 `北岸`、不同运营方 `北岭`、同运营方不同线路 `松林`） | 站名消歧：`站名（城市）`、`站名（运营方）`、`站名（线路集合）` |
| 一座改名的车站（原名 `石桥`，2022 年为消除同名改为 `沙坪`） | 车站历史名称；按乘车日期取站名时标签随之变化 |
| 一座非客运车站（`谢家桥`） | 不办理客运的车站 |

数据里的每一处安排都对应上表的一项。`packages/application/test/showcase.test.mjs` 会检查这些形状确实还在（环线能展平、支线与主线共用区间、停运与直通对存在），改数据时请一并更新它。

## 布局

```text
demo-showcase/
├─ generate.mjs                    # 重新生成下面所有内容（唯一来源）
├─ envelopes/
│  ├─ reduced-envelope.json        # prepare 脚本发布给浏览器的信封
│  └─ reviewed-mapping.json        # 直通对与跨快照白名单
└─ scenarios/
   └─ demo-showcase-full/
      ├─ manifest.json
      ├─ source-use.json
      ├─ policies.json
      ├─ reader-payload.json
      └─ LICENSE-OSM.md
```

## 命令

```bash
npm run demo:generate:showcase   # 重新生成本目录的已提交文件
npm run dev                      # 发布展示数据并在 http://127.0.0.1:5173 启动
npm run build                    # 类型检查后按展示数据构建
```

`npm run dev` 与 `npm run build` 都用 `--data-root demo-showcase` 发布这里的信封；自动检查（`npm test`、`npm run verify:gates`）继续跑在 `demo/` 的小数据集上。改指另一个数据根的方法见 [`apps/web/README.md`](../apps/web/README.md)。

## 限制

- 图片导出按设计拒绝合成数据（它需要授权数据的署名文本），展示数据同样导出不了。
- 两条线共用同一段物理轨道的真实共线（例如上海 3/4 号线）当前数据模型不支持，所以这里没有；能演示的是两条运营线路共用区间。
- 没有跨快照历史：`reviewed-mapping.json` 的 `snapshots` 为空，只声明直通对。
- `generate.mjs` 是已提交文件的唯一来源，不要手工编辑生成的 JSON；改完数据集重跑 `node demo-showcase/generate.mjs`。
